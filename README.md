# מערכת בד״ח דיגיטלית · Digital Inspection Checklist

מערכת מקצועית, מלאה ועובדת לניהול וביצוע בד״חים (דפי בדיקה/משימות) — בעברית מלאה (RTL),
מותאמת למסך מגע ולעבודה על טאבלט Zebra, עם חתימה בעט (Stylus), אישור נעול, היסטוריה,
והפקת PDF / Excel / הדפסה.

> ממשק בעברית · הערות בקוד באנגלית.

---

## עקרונות ארכיטקטורה

הבחירות נקבעו לפי סביבת העבודה שהוגדרה:

| דרישה | החלטה |
|------|-------|
| מערכת הפעלה לא ידועה (Windows / Android) | **אפליקציית Web (PWA)** — רצה בדפדפן, זהה בכל מערכת הפעלה |
| רצה גם על הטאבלט וגם על מחשב | דפדפן על שניהם; ניתן להתקין כאפליקציה (PWA) |
| חובה לעבוד ללא אינטרנט | **Offline-first** — מסד נתונים מקומי (IndexedDB) + Service Worker |
| מאגר משותף בעתיד | **סנכרון מבוסס קובץ** (USB / ייצוא-יבוא), מיזוג "מוסיף בלבד" עם UUID + מזהה מכשיר |
| חתימת עט Zebra | **Canvas + Pointer Events** — תומך בעט/Stylus אמיתי (Windows Pen / Android), כולל לחץ עט |
| מאשרים | **חשבונות אישיים** — המערכת יודעת מי אישר; מניעת אישור-עצמי לפי User ID |

**אין שרת תמידי** — כל מכשיר עצמאי. העברת נתונים בין מכשירים מתבצעת דרך קובץ (מסך גיבוי/סנכרון).

### Tech Stack

- **Frontend:** React 18 + TypeScript + Vite
- **עיצוב:** Tailwind CSS (RTL), Touch-friendly, פונט Rubik
- **מסד נתונים מקומי:** IndexedDB דרך Dexie
- **אבטחה:** bcrypt (hash סיסמאות), RBAC בשכבת השירותים, ניתוק מנהל אוטומטי
- **חתימה:** Canvas + Pointer Events
- **ייצוא:** ExcelJS (‎.xlsx‏, RTL), jsPDF + html2canvas (‎PDF A4‏), הדפסת דפדפן
- **בדיקות:** Vitest + fake-indexeddb

## התקנה והרצה

דרוש Node.js 18+ (פותח על Node 22).

```bash
npm install         # התקנת תלויות
npm run dev         # הרצת שרת פיתוח (http://localhost:5173)
npm run build       # בניית גרסת production לתיקיית dist/
npm run preview     # תצוגה מקדימה של גרסת ה-production
npm test            # הרצת מערך הבדיקות
npm run typecheck   # בדיקת טיפוסים
```

### התקנה כאפליקציה (PWA)

לאחר `npm run build`, הגישו את תיקיית `dist/` משרת סטטי כלשהו (או `npm run preview`).
בטאבלט/מחשב: פִּתחו בדפדפן → תפריט → **"התקן אפליקציה" / "הוסף למסך הבית"**.
האפליקציה תיפתח במסך מלא ותעבוד גם ללא אינטרנט.

> אריזה ל-Windows (‎Setup.exe‏) או Android (‎APK‏) היא שלב עטיפה דק מעל אותו קוד (למשל Capacitor
> ל-Android או wrapper ל-Windows), ותתבצע לאחר שיתברר הדגם המדויק של ה-Zebra.

## משתמשי דמו (יש לשנות סיסמאות בהתחברות ראשונה)

| תפקיד | שם משתמש | סיסמה |
|------|----------|-------|
| מנהל (ADMIN) | `admin` | `admin123` |
| מבצע (PERFORMER) | `performer` | `1234` |
| מאשר (APPROVER) | `approver` | `1234` |

בהפעלה ראשונה נוצרים אוטומטית: המשתמשים לעיל, שלוש ההרשאות, ותבנית דמו **"בדיקה יומית"**
(מנוע / מערכת חשמל / אזור עבודה).

---

## תרחיש עבודה (End-to-End)

1. **מנהל** מתחבר → יוצר משתמשים ותבניות (עורך תבניות עם גרירה, תמונות לכל סעיף).
2. **מבצע** מתחבר → *בד״ח חדש* → בוחר תבנית → ממלא פרטים (שם/מספר/תאריך אוטומטי, שם מבצע אוטומטי).
3. מסמן לכל סעיף **תקין / לא תקין** (בלעדי). "לא תקין" פותח **פירוט תקלה** + **צירוף/צילום תמונה**.
4. **חותם** בעט על משטח החתימה → **שמור והעבר לאישור** (בדיקת שלמות מלאה קודם).
5. **מאשר אחר** לוחץ 🔒 *פתיחת אישור* → מזדהה (שם משתמש + סיסמה). המערכת חוסמת אישור עצמי
   ומשתמש ללא הרשאת מאשר — **בשכבת הלוגיקה, לא רק ב-UI**.
6. המאשר חותם בעט → **אשר וסגור** → הבד״ח **ננעל** (סטטוס: מאושר).
7. מההיסטוריה מפיקים **PDF / Excel / הדפסה** — כולל **שתי החתימות** האמיתיות וסטטוס בולט.

│  ├─ approval.ts   # אימות מאשר, מניעת אישור-עצמי, אישור סופי
│  ├─ adminForms.ts # עריכת מנהל + ביטול אישור בעת שינוי תוכן

│  ├─ images.ts     # העתקת תמונות לנתונים מנוהלים + כיווץ

## נקודות אבטחה מרכזיות

- **סיסמאות** נשמרות כ-hash (bcrypt) בלבד — לעולם לא כטקסט גלוי.
- **מניעת אישור עצמי** (`approver_user_id != performer_user_id`) נבדקת לפי User ID גם באימות
  וגם באישור הסופי (defense-in-depth) — לא לפי שם שהוקלד.
- **בדיקות הרשאה** מתבצעות בשכבת השירותים, לא רק בהסתרת כפתורים.
- **Snapshot**: כל בד״ח שומר עותק קפוא של תוכן התבנית — שינויים עתידיים לא משפיעים על בד״חים ישנים.
- **נעילה**: בד״ח מאושר אינו ניתן לעריכה על ידי משתמש רגיל.
- **Audit Log + ביטול אישור**: שינוי תוכן מהותי של בד״ח מאושר על ידי מנהל מבטל את האישור
  ומחייב אישור מחדש, כדי שהחתימה הישנה לא תאשר מידע ששונה.
- **ניתוק מנהל אוטומטי** לאחר חוסר פעילות (ניתן להגדרה).

## בדיקות

מערך בדיקות (Vitest) מכסה: hash והתחברות, הרשאות, Snapshot, בלעדיות תקין/לא תקין, ולידציה
ונעילה, **מניעת אישור עצמי**, זרימת אישור מלאה, יומן ביקורת, וסנכרון/גיבוי מבוסס קובץ.

```bash
npm test
```

הזרימה המלאה (התחברות → ביצוע → חתימה → אישור → נעילה → PDF עם שתי חתימות) נבדקה גם
בדפדפן אמיתי (Chromium) מקצה לקצה.
