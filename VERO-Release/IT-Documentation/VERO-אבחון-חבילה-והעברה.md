# VERO — דוח אבחון חבילת ההפצה והוראות העברה מאושרת

> נכתב לאחר שהקובץ "עבר הלבנה אך Windows מדווח שהוא פגום/נפגע". המסקנה: **חבילת המקור תקינה ושלמה** — הפגימה נוצרה אחרי המקור (ככל הנראה בתהליך ההלבנה ששינה את הבתים). להלן הבדיקות, ה-SHA-256, ומה להעביר לגורמי המחשוב.

## 3. הבדיקה המכרעת — השוואת SHA-256 לפני/אחרי הלבנה

הריצו על הקובץ **שהתקבל אחרי ההלבנה** והשוו לטבלה למעלה:

**PowerShell:**
```powershell
Get-FileHash .\VERO-Setup-1.0.0.exe -Algorithm SHA256
```
**או Command Prompt:**
```cmd
certutil -hashfile VERO-Setup-1.0.0.exe SHA256
```

- **ה-hash שונה מהמקור** → **ההלבנה שינתה את הקובץ**. זו סיבת הפגימה: קובץ `.exe` הוא ארכיב — כל שינוי בבתים שובר אותו ו-Windows מדווח "פגום". ראו §5.
- **ה-hash זהה** → הקובץ שלם; הבעיה בהרצה (SmartScreen / אנטי-וירוס / בדיקת בנייה על Windows). ראו §6.

## 4. איזה קובץ זה — Setup, Portable, או תיקייה?

| קובץ | מה זה | דורש תיקייה? |
|---|---|---|
| `VERO-Setup-1.0.0.exe` | מתקין (NSIS), per-user, בלי Administrator | **לא** — קובץ יחיד |
| `VERO-Portable-1.0.0.exe` | נייד, הרצה ישירה בלי התקנה | **לא** — קובץ יחיד |
| `VERO-App-1.0.0.zip` | **אפליקציה פרוסה בתוך ZIP** | מחלצים את ה-ZIP לתיקייה ומריצים בתוכה `VERO.exe` |

כל שלושתם מכילים **בדיוק אותה אפליקציה**. ה-ZIP הוא ההמלצה להלבנה — ראו §5.

## 5. אם המקור תקין וההלבנה פגמה — מה להעביר לגורמי המחשוב

**אין לשנות את קוד VERO, ואין לעקוף/להסוות.** הבעיה אינה בתוכנה אלא בכך שתהליך ההלבנה משנה קובץ הרצה.

מה להסביר ל-IT / אבטחת מידע:
1. **קובץ `.exe` אינו "מסמך" לניקוי.** מערכת הלבנת מסמכים שמשנה/בונה-מחדש בתים **הורסת** ארכיב הרצה. צריך אחת מהדרכים:
   - **מסלול התוכנה של הארגון** (Whitelisting / אישור תוכנה) שמעביר בינאריים **ללא שינוי** (hash נשמר). זה המסלול הנכון ל-exe.
   - **חריג/Exception** לקובץ חתום, או **חתימה דיגיטלית** של הארגון (Authenticode) — חתימה גם מאפשרת ל-Windows לאמת שהקובץ לא שונה.
2. **לנסות את `VERO-App-1.0.0.zip`.** הרבה שערי הלבנה מעבירים ZIP ע״י פתיחה-סריקה-אריזה-מחדש **בלי לשנות את הקבצים הפנימיים**, בעוד שהם "מנטרלים" exe. אם ה-ZIP עובר ונשאר תקין (בדקו SHA של הקבצים שבתוכו) — מחלצים לתיקייה ומריצים `VERO.exe`. **הרצה ישירה, בלי התקנה ובלי Administrator.**
3. בכל מקרה — **לאמת SHA-256 לפני ואחרי** כל שלב העברה, כדי לדעת היכן בדיוק הקובץ משתנה.

## 6. בדיקת הרצה על Windows (חובה לפני הפצה)

בדיקת ההרצה חייבת להתבצע על מכונת Windows אמיתית (לא ניתן בסביבת הבנייה האופליינית):
1. על מכונת Windows 10/11 x64, **לפני הלבנה**, הריצו את `VERO-Setup` או `VERO-Portable`.
2. אם קופץ SmartScreen ("Windows protected your PC") → **More info → Run anyway** (כי לא חתום).
3. אם הקובץ "חסום": לחיצה ימנית → **Properties** → **Unblock** → Apply.
4. ודאו: פתיחה, עברית/RTL, שמירת נתונים, בד״חים/חתימות/הסמכות/מבחנים.

> הערה: הבינארי נבנה בסביבת Linux דרך Wine ולא נבדק על Windows. אם הבדיקה **לפני הלבנה** נכשלת (ולא רק אחרי), יש לבנות על מכונת Windows אמיתית לפי `vero-desktop/BUILD.md` (`npm install` + `npm run build:win`) — זה מפיק בינארי שנבדק מקומית.

## 7. סיכום פעולה מומלץ

1. **עכשיו:** הריצו §3 (השוואת SHA) על הקובץ אחרי ההלבנה → כך נדע בוודאות אם ההלבנה היא האשם.
2. **במקביל:** נסו את `VERO-App-1.0.0.zip` דרך ההלבנה (§5.2).
3. **מול IT:** בקשו את מסלול אישור התוכנה שמעביר בינאריים ללא שינוי, או חתימה/חריג (§5.1).
4. בדיקת הרצה על Windows לפני הפצה רחבה (§6).
