# VERO — מוכנות להתקנה ארגונית Offline

מסמך זה מתאר את מצב המוכנות של VERO להתקנה כאפליקציה עצמאית על טאבלט Zebra
בסביבה ארגונית סגורה, ואת מה שנותר להשלים לאחר קבלת פרטי המכשיר והארגון.

> **החלטת Packaging טרם התקבלה — במכוון.** לא נבחר פורמט Installer סופי ולא
> בוצע שינוי ארכיטקטורה לצורך התקנה, עד לקבלת: (1) דגם ה-Zebra המדויק,
> (2) מערכת ההפעלה והגרסה, (3) דרישות ההתקנה/ההלבנה (BGN). ראו "צעדים הבאים".

---

## 0. חשוב מאוד — Preview מרוחק מול קובץ מקומי (שורש תקלת ה-Offline)

**כתובת ה-Preview של Claude (`https://claude.ai/code/artifact/...`) היא אתר
מרוחק המתארח באינטרנט.** פתיחתה ב-Edge מורידה את הדף מהרשת בכל פעם; לכן כשמכבים
Wi-Fi הדפדפן מציג "אין אינטרנט" — לא בגלל VERO אלא בגלל שכתובת ה-Preview עצמה
דורשת רשת. **אין להשתמש בכתובת ה-Preview כגרסה הסופית.**

הגרסה המקומית של VERO היא **קובץ יחיד `VERO.html`** שכל ה-Frontend, ה-CSS,
ה-JavaScript, הפונט, האייקונים וספריות ה-PDF/Excel מוטמעים בתוכו. הוא נפתח
ישירות מהמכשיר (`file://` או WebView/קיוסק) **ללא רשת כלל**, והנתונים נשמרים
מקומית ב-IndexedDB.

**בנייה של הקובץ המקומי:**
```bash
npm ci
npm run build:offline     # פלט: dist/VERO.html — קובץ יחיד, offline מלא
```

נבדק אוטומטית בדפדפן Chromium עם **ניתוק רשת קשיח** (`offline`) ומ**פרופיל נקי**

1. מסך הכניסה נטען Offline מפרופיל קר — ✅
2. Login למשתמש מקומי — ✅
3. פתיחת "בדיקה חדשה" ויצירת בד״ח (נשמר ל-IndexedDB) — ✅
4. סימון סעיף "תקין" + שמירת מספר בד״ח — ✅
5. **סגירה ופתיחה מחדש (סימולציית Restart)** — הנתונים נשמרו: בד״ח קיים,

6. הפקת **Excel** ו-**PDF** אמיתיים Offline (ספריות אמיתיות, לא stub) — ✅

## 1. עקרון: הכל מקומי (Offline‑first)

VERO רצה ללא אינטרנט כלל. אין תלות ריצה (runtime) באף אחד מהבאים:

| רכיב | מצב |
|------|-----|
| Internet / Cloud | ❌ אין |
| CDN | ❌ אין |
| שירות Authentication חיצוני | ❌ אין — אימות מקומי מול IndexedDB |
| Fonts מהאינטרנט | ❌ אין — **Heebo מוטמע מקומית** (`src/assets/fonts`) |
| Assets מהאינטרנט | ❌ אין — כל האייקונים/הגרפיקה מקומיים או inline SVG |
| Analytics / Telemetry | ❌ אין |
| Auto‑Update דרך האינטרנט | ❌ אין |

**אומת בבנייה:** טעינת האפליקציה מבצעת **אפס בקשות רשת חיצוניות**
(נבדק ב-headless browser — `external requests during load: none`).

## 2. מה בוצע בהכנה זו

- **פונטים מקומיים:** Heebo (רישיון SIL OFL) הורד והוטמע כקבצי `woff2`
  מקומיים עם `@font-face` ו-`unicode-range` (עברית + לטינית). הוסר לחלוטין
  ה-`<link>` ל-Google Fonts. יש fallback ל-`system-ui`.
- **אייקון אפליקציה מקצועי של VERO:** נוצר מלוגו VERO הקיים (ריבוע Navy מעוגל
  עם ה-V הדו-גוני). קובץ מקור `public/icon.svg` + PNG ברזולוציות
  48/72/96/128/144/180/192/256/512/1024, כולל גרסאות **maskable** (192/512)
  ל-Android, ו-`apple-touch-icon`. לאחר ההתקנה יופיע אייקון VERO במסך המכשיר,
  ולחיצה עליו תפתח את VERO ישירות במסך הכניסה.
- **Web App Manifest ממותג VERO:** שם "VERO", `display: standalone`
  (עם `display_override: [fullscreen, standalone, minimal-ui]`), צבע רקע/ערכה
  Navy, `start_url` יחסי, `scope` יחסי, כל האייקונים.
- **Service Worker מוקשח (`public/sw.js`):** precache של קליפת האפליקציה,
  cache‑first לכל הנכסים (JS/CSS/פונטים/תמונות), ו-network‑first לניווט עם
  fallback ל-`index.html`. פונה **רק** ל-origin המקומי, לעולם לא לחוץ.
- **תחושת אפליקציה ייעודית (לא דפדפן):** meta לתצוגת מסך מלא
  (`mobile-web-app-capable`, `apple-mobile-web-app-*`, `viewport-fit=cover`),
  נעילת zoom, ביטול overscroll/pull‑to‑refresh ו-tap delay.

## 3. שמירת נתונים מקומית (Persistence)

כל נתוני המערכת נשמרים **מקומית ב-IndexedDB** (דרך Dexie): משתמשים, תבניות,
בד״חים, תוצאות, תמונות, חתימות, אישורים, יומן ביקורת והגדרות. הנתונים
**שורדים סגירת אפליקציה ו-Restart** של הטאבלט. מחיקה מתרחשת רק אם המשתמש/הארגון
מוחק את נתוני האפליקציה במפורש.

יכולות ה-Offline המלאות שנתמכות ללא רשת: Login מקומי, ביצוע בד״ח, שמירה,
תמונות, חתימה בעט, העברה למאשר, אישור ממשתמש אחר (חשבון נפרד), היסטוריה,
סטטיסטיקות, PDF, Excel, Print Preview, ייצוא וגיבוי לקובץ.

> העברת נתונים בין מכשירים מתבצעת בקובץ (ייצוא/ייבוא ב-USB) — ללא רשת.

## 4. הערה לתהליך ההלבנה/אישור

- ספריית **jsPDF** מכילה מחרוזת סטטית של כתובת CDN
  (`.../pdfobject.min.js`) בתוך נתיב תצוגת PDF שאיננו בשימוש ב-VERO
  (אנו יוצרים PDF דרך `addImage` בלבד). המחרוזת **אינה נטענת בזמן ריצה**
  ואינה מהווה תלות רשת. אם דרישות ההלבנה מחייבות אפס מחרוזות CDN בבינארי,
  נתקן זאת (patch/הסרה) בשלב ה-Packaging.

## 5. מסך מלא ויציאה בטוחה

- הבנייה מוגדרת ל-`display: standalone` (מומלץ) — ללא סרגלי דפדפן, עם ניווט
  מערכת בטוח. `display_override` כולל `fullscreen` למקרה שהארגון ירצה מסך מלא
  לחלוטין; מצב קיוסק אמיתי (נעילת יציאה) הוא הגדרת מכשיר/MDM
  (למשל Zebra Enterprise Home Screen / StageNow) שתיקבע בשלב ההתקנה.
- **יציאה בטוחה:** כפתור "יציאה" בכותרת מנתק את המשתמש ומחזיר למסך הכניסה,
  ללא מחיקת נתונים.

## 6. צעדים הבאים (לאחר קבלת פרטי המכשיר)

יש לספק כדי לסיים את ה-Packaging:

1. **דגם Zebra מדויק** (למשל TC21/TC26/ET40…).
2. **מערכת ההפעלה והגרסה** (למשל Android 11/13; WebView version).
3. **דרישות ההתקנה/ההלבנה של סביבת BGN** (פורמט חבילה, חתימה, הרשאות,
   הפצה דרך MDM/StageNow, מדיניות קיוסק).

מסלולי Packaging אפשריים (ייבחר לאחר קבלת הפרטים — ללא שינוי בקוד הליבה):

- **APK מבוסס WebView / TWA** שאורז את `dist/` כנכסים מקומיים (offline מלא כבר
  בהפעלה הראשונה, ללא צורך ב-SW).
- **דפדפן קיוסק / Enterprise Home Screen** שמצביע לקבצים המקומיים.
- **PWA מותקנת** (Add to Home Screen) — כבר נתמכת ע״י ה-Manifest וה-SW הנוכחיים.

## 7. בנייה

```bash
npm ci
npm run build          # פלט: dist/ — נכסים מקומיים בלבד (base יחסי './')
```

`dist/` הוא סטטי לחלוטין וניתן להגשה מקובץ מקומי/WebView ללא שרת ואינטרנט.
(בנייה חלופית ל-preview בקובץ יחיד: `SINGLEFILE=1 npm run build`.)
