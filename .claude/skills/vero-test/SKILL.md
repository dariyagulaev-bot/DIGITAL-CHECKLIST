# vero-test — בדיקות ואימות VERO

מיומנות להרצה וכתיבה של בדיקות, ולאימות אמיתי של שינויים.

## מתי להשתמש
- לפני מסירת כל שינוי מהותי.
- כשצריך לכתוב בדיקת יחידה חדשה או בדיקת E2E.
- לבדיקת רגרסיה לפי מערכת / תת־מערכת / דרג.

## מבנה אמיתי בפרויקט
- **יחידה:** Vitest — קבצי `src/**/*.test.ts` (כ-23 קבצים, ~138 בדיקות). הרצה: `npm test` (= `vitest run`) או `npx vitest run <path>`.
- **טייפים/בנייה:** `npm run build` (`tsc -b && vite build`).
- **E2E (נבדק בפועל בסשן):** בניית `dist/` → `python3 -m http.server 8099 --directory dist` → Playwright Chromium (`chromium.launch({args:['--no-sandbox']})`). כניסה לדוגמה: admin/admin123, performer/1234, approver/1234. אפשר לזרוע נתוני דמה ישירות ל-IndexedDB (DB בשם `digital_checklist`) דרך `page.evaluate`.
- מנוע המדידה טהור וניתן לבדיקה: `src/services/measurements.ts` (ראה `measurements.test.ts`, `grid.test.ts`).

## תהליך עבודה (שלב-אחר-שלב)
1. הרץ `npm run build` — חייב לעבור נקי.
2. הרץ `npm test` — כל הבדיקות חייבות לעבור. אם נכשל — אבחן (vero-debug), אל תשבית/תמחק בדיקה.
3. למיגרציה/לוגיקה חדשה — הוסף בדיקת יחידה ממוקדת (pass + fail + edge).
4. לזרימת UI — בצע E2E: זרע נתוני דמה, בצע את התרחיש (לדוגמה: בדיקה לפי מערכת→תת־מערכת→דרג), וצלם מסך לאימות.
5. ודא כיסוי לשלושת הצירים כשרלוונטי: **מערכת, תת־מערכת, דרג**.

## כללי ברזל
- **אסור** למחוק/להשבית/לדלג בדיקה כדי "לעבור". תקן את השורש.
- נתוני בדיקה = דמה בלבד. **אין** להשתמש בנתוני אמת או מסווגים.
- אין להריץ בדיקות שמשנות נתוני אמת או מוחקות מסד ללא אישור.
- בדיקות רצות מקומית/אופליין; אין להעלות קוד או נתונים לשירות חיצוני.

## קריטריוני הצלחה
- build נקי + כל בדיקות היחידה ירוקות + E2E של התרחיש שנגעת בו עובר (עם צילום).

## דיווח (בעברית)
- מה נבדק ואיך (יחידה/E2E), עם הפלט/צילום.
- הבחן במפורש בין **בדיקות שבוצעו בפועל** לבין **בדיקות שעדיין נדרשות** (למשל הרצה על טאבלט אמיתי, או תרחיש שלא כוסה).
- ספירת בדיקות לפני/אחרי אם הוספת.
