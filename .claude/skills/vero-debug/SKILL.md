# vero-debug — איתור ותיקון תקלות ב-VERO

מיומנות לאבחון שיטתי של תקלות, מהשורש, בלי לשבור יכולות קיימות.

## מתי להשתמש
- שגיאת build/TypeScript, חריגה בזמן ריצה, מסך לבן, רכיב שלא נטען.
- בעיות מסד נתונים מקומי (Dexie/IndexedDB) או מיגרציות גרסה.
- בעיית טעינה אופליין (`file://`), תקלת RTL, או ייצוא PDF/Excel שבור.

## מבנה אמיתי בפרויקט
- אפליקציית React+TS+Vite; מסד מקומי Dexie ב-`src/data/db.ts` (מיגרציות לפי גרסה — כרגע v15).
- שירותים ב-`src/services/*` (כולל בדיקות `*.test.ts`), ייצוא ב-`src/exports/*`.
- בנייה אופליין: `npm run build:offline` → `dist/VERO.html` (IIFE יחיד, `scripts/finalize-offline.mjs`).
- E2E קיים בפועל בסשן: הגשה מקומית `python3 -m http.server 8099 --directory dist` + Playwright Chromium `--no-sandbox`.

## תהליך עבודה (שלב-אחר-שלב)
1. **שחזר** את התקלה: הרץ `npm run build` ו/או הגש `dist/` והסתכל בקונסול (`pageerror`/console).
2. **צמצם** לשורש: קובץ/שירות/טוקן ספציפי. אל תתקן סימפטום.
3. אם קשור למסד: בדוק את הגדרת הטבלאות והמיגרציה ב-`db.ts`; זכור ש-IndexedDB לכל דפדפן/מכשיר נפרד.
4. אם קשור לאופליין: ודא ש-`VERO.html` נטען מ-`file://` ללא שגיאות מודול (ה-build הוא IIFE קלאסי בכוונה).
5. תקן מינימלית, ואז ודא שלא נשברו בדיקות קיימות.

## כללי ברזל
- אין למחוק נתונים, לאפס מסד, או לשנות מיגרציות קיימות בלי אישור — זה עלול למחוק בד״חים/טיוטות אצל משתמשים.
- אין לשנות הרשאות, חתימות, או התנהגות קיימת כדי "לעקוף" תקלה.
- לשמור על עבודה אופליין ועל שמירת טיוטות אוטומטית.
- אין להשתמש בנתוני אמת/מסווגים לשחזור תקלה — השתמש בנתוני דמה.

## בדיקות וקריטריוני הצלחה
- `npm run build` נקי, ו-`npm test` (vitest) ירוק.
- שחזור התקלה המקורי כבר לא קורה (הדגם לפני/אחרי).
- לא נוצרו רגרסיות: הרץ את מלוא חבילת הבדיקות.

## דיווח (בעברית)
- מה הייתה התקלה, מה היה **שורש הבעיה**, ומה תוקן (קבצים).
- אילו בדיקות **בוצעו בפועל** (פלט/צילום) ואילו **נותרו**.
- אם לא ניתן לשחזר/לתקן בבטחה — דווח מה חסר ומה ההמלצה, אל תמציא תיקון.
